# Modelo — B11
- fleet_vehicles: id UUID PK; identifier varchar(100) e plate varchar(20) normalizados maiúsculos e únicos; kind van/micro/bus; seats inteiro >0; active bool; version inteiro positivo; week JSONB nullable (sete listas de faixas). Identificação/placa não vazias. Sem validação legal de placa ou dados reais presumidos.
- fleet_drivers: id UUID PK; name varchar(200) não vazio; phone varchar(16) normalizado internacional; active bool; version inteiro positivo. Sem login/credencial/FK para conta.
- fleet_exceptions: vehicle_id UUID FK + date PK, windows JSONB nullable (lista; vazia indisponível; null herda semana). Compartilha revisão do veículo; sem exclusão destrutiva. PUT windows=null remove a sobreposição por marcar retorno à semana (coluna nullable); ausência e null têm mesma semântica de herança.
- Cada faixa: stage collection/intermunicipal/distribution; start inteiro 0..2879; end inteiro >start e <=2880; exatamente três campos. Faixas da mesma etapa não se sobrepõem; adjacência permitida. Limite técnico de 30 faixas por dia.
- Proposta não persistida: date, trips (1..100). Local: vehicleId, groupId, stage collection/distribution, driverId,start,end. Intermunicipal: vehicleId,universityId,outbound e return, cada qual driverId,start,end; retorno começa após fim de ida. Ocupação integral start de ida..end de retorno. Colisões por veículo consideram permanência; motorista considera seus trechos de condução.
Migração aditiva com FKs/índices e CHECKs. App SELECT/INSERT/UPDATE, sem DELETE/DDL. down bloqueia se existir cadastro para não apagar dados.
